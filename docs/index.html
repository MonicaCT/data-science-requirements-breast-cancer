Executive summary

What this project demonstrates

This repository documents the early phases of a data science project: dataset search and comparison, quantitative selection, data-quality assessment, exploratory statistical analysis, and functional and non-functional requirements for a biomedical analytical system.

Dataset selection

Compares Breast Cancer Wisconsin Diagnostic, Diabetes Progression and Wine Recognition using measurable criteria rather than preference.

Data-quality assessment

Reports completeness, duplicates, target balance, outlier flags, correlation structure and variables with strong effect sizes.

Requirements engineering

Defines functional and non-functional requirements grounded in reproducibility, traceability, interpretability and maintainability.

The findings support requirements and exploratory understanding. They are not clinical advice and do not constitute a deployed diagnostic model.

Completeness is strong

Methodology

Existing workflow summarized

The methodology is reused from the README and final report. No scripts were executed for this update.

1. Search local datasets

Three candidate datasets available locally in scikit-learn are considered.

2. Compare candidates

Datasets are compared using normalized criteria for size, dimensionality, completeness, readiness, interpretability and impact.

3. Select dataset

Breast Cancer Wisconsin Diagnostic is selected as the highest-scoring dataset.

4. Build variable dictionary

Variables are documented with type, description, range, unit, importance and outlier notes.

5. Assess data quality and EDA

Missingness, duplicates, class balance, descriptive statistics, correlations and effect sizes are documented.

6. Define requirements and report

Functional and non-functional requirements, final figures, tables and HTML/PDF report are produced.

Limitations

Responsible interpretation

  • This is an academic and methodological project, not a clinical decision tool.
  • Outputs must not be interpreted as medical advice, patient-level diagnosis or individual recommendation.
  • No predictive model is trained in the current scope.
  • Later modelling phases should use stratified splits, feature-redundancy controls and appropriate validation.
  • Dataset selection and requirements are based on available local datasets and documented project constraints.
